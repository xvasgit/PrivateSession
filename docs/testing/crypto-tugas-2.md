## Mechanism and product boundaries

Transcript and review text require confidentiality and tamper detection at rest. Standard Node/Web Crypto AES-256-GCM supplies both in one authenticated-encryption operation. A plain hash would not authenticate data against an attacker; password hashing instead uses Better Auth's salted scrypt and is not reversible content encryption. See [KEPUTUSAN.md](../../KEPUTUSAN.md) and the [current README](../../README.md).

| Parameter          | Implemented value                                                                                                                                                                             |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Key                | Original CSPRNG-generated 32-byte AES key, configured privately as canonical Base64 `DATA_ENCRYPTION_KEY`; imported non-exportable. No automatic regeneration.                                |
| IV / nonce         | Fresh CSPRNG 12-byte IV per encryption, including edits. Sampling tests check freshness; they do not prove collisions impossible. Never intentionally reuse an IV with the same key.          |
| Authentication tag | 128 bits, appended to ciphertext by Web Crypto; ciphertext/tag and IV stored in PostgreSQL BYTEA columns.                                                                                     |
| Transcript AAD     | `meeting-session:v1:transcript-segment:v1:<sessionId>:<sequence>`                                                                                                                             |
| Review AAD         | `meeting-session:v1:meeting-review:v1:<meetingId>`                                                                                                                                            |
| Review payload     | Validated version-1 JSON: summary, insights, followUps; maximum 10,000 characters per field.                                                                                                  |
| Failure response   | Rejected operation, no unauthenticated plaintext returned. Product adapters use generic authentication/decryption errors. An unreadable stored review cannot be silently replaced or cleared. |

Meeting title/code/time/owner and segment order remain plaintext metadata. The server decrypts for authorized display: this is not end-to-end encryption. The original encryption key is separate from the authentication signing secret and password hashes. Transcript/review content still share the original AES key with distinct AAD; **purpose-derived content keys are not implemented**. That remains a highest-tier rubric improvement, not something this matrix claims to test. Retain the original key and protected recovery copies outside Git; IV reuse can compromise both confidentiality and integrity. Non-exportability does not protect against the running server/operator.
