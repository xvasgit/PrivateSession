# PemWeb Tugas 2 — CRUD and Server Validation Results

Product: PrivateSession. Reviewed on 2026-11-06 against the current accounts/ownership working tree on `main` (base commit `2444066`; changes not yet committed or tagged). These results describe the integrated product, not the historical Module 6 shared-account lab.

## Scope and evidence sources

The assessed entities are `MeetingSession` and `TranscriptSegment`, related one-to-many. Meeting ownership comes from the authenticated account. Meeting codes are unique within an owner; segment sequence is unique within a meeting. Transcript content is encrypted in PostgreSQL. See the [schema](../../prisma/schema.prisma), [migrations](../../prisma/migrations), [seed](../../prisma/seed.ts), [Server Action](../../app/meetings/actions.ts), [repository](../../lib/meetings/repository.ts), and [validation schema](../../lib/meetings/schema.ts).

Evidence is separated deliberately:

- **Manual UI:** 17 screenshots captured by the student and visually reviewed on 2026-11-06. They show inputs and visible outcomes, not an independent database inspection or proof of refresh/restart persistence.
- **Database:** the current owner-aware [database script](../../scripts/test-meeting-db.ts) passed **13/13** on 2026-11-06 during implementation. PASS numbers below refer to that script. This documentation task did not rerun database mutations.
- **Browser:** the database-enabled production suite passed **63/63** at 390/768/1280 px on 2026-11-06. The [meeting browser tests](../../tests/e2e/meetings.spec.ts) combine real UI actions with PostgreSQL queries. These are separate synthetic fixtures, not the student's meeting IDs.
- **Quality:** the subsequent pre-submission review passed lint, types, formatting and **145/145** unit tests. Sources and limitations are retained in [EVALUASI.md](../../EVALUASI.md).

All examples must remain synthetic. No credentials, session cookies or encryption keys belong in evidence.

## Reproduction setup

1. Follow [README setup](../../README.md), preserving the original encryption key and existing database. Apply committed migrations and provision local accounts as documented; never reset the database for screenshots.
2. Sign in with an active account and complete initial-password replacement. Use that same account throughout a manual CRUD sequence.
3. Create disposable meetings with unique codes, for example `PAW-T2-A01` and `PAW-T2-B01`. Do not delete seed or another assessment's records. The supplied images instead use `MPPL-01`, title `Kuliah Online MPPL`, at `/meetings/279/`.
4. Capture creation, reads, updates and validation before deletion. Reload after a successful save when reproducing persistence checks. A caption should distinguish observed UI behavior from database assertions.

Run the database scenarios from the application root:

```powershell
npm run db:test
```

The script creates a unique synthetic account/session and records, checks real Prisma/PostgreSQL results, and removes only its own fixtures. For UI/database checks, build with the documented Webpack fallback, then run:

```powershell
$env:PLAYWRIGHT_DATABASE='1'
$env:PLAYWRIGHT_PORT='3101'
npm run test:e2e -- --workers 2
Remove-Item Env:PLAYWRIGHT_DATABASE
Remove-Item Env:PLAYWRIGHT_PORT
```

Choose an unused port; do not stop someone else's server. The commands above are reproduction instructions, not new executions claimed by this document.
